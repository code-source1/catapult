Optimization targets: Large area
AREA_GOAL

Description

The AREA_GOAL directive specifies a size goal for area optimization.

In the first solution (test.v1), the design has no area or design goal set. Catapult will automatically optimize for area.

The timing report lists the instances in the critical path that Catapult chose in order to meet the timing requirements. When it considers various implementation possibilities, Catapult attempts to choose the smallest implementations that still meet the timing constraint (e.g., clock period).

IMAGE

In the second solution (test.v2), DESIGN_GOAL has been set to optimize latency over area, AREA_GOAL is set to 1200. In this case, there is a slight improvement to slack.

Command syntax example:
directive set /test/core -AREA_GOAL 1200

Why this target fits:
AREA_GOAL gives Catapult an explicit area budget, so the scheduler/resource selector prefers
smaller implementations that still meet timing. It is therefore a direct template for Large area.
It may indirectly reduce power by reducing hardware, but power is not the primary directive target.
